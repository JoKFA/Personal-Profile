## 0. 一句话

**信息蚀刻在磨砂里：没有授权，它只是一层霜；授权的那一刻，光从里面把它点亮。**

网站从不"装饰"安全，而是让安全**发生**：密文是霜，解密是霜散开，权限是光。它和 PV 学的是同一种语法（磨砂、透光、长焦、浅景深），但这个隐喻是我们自己的，PV 里没有。

## 1. 五条总则

1. **一个世界，一种光。** 光要么来自物体内部，要么来自左上方一盏柔和的暖色主光。没有来源的光晕一律不要。
2. **霜是默认，清晰要挣来。** 未打开的东西都隔着霜；打开就是霜散开。黑色涂抹条和随机字符乱码一律不再使用（真正的数据例外，比如哈希值本身）。
3. **一帧一个焦点。** 其他东西退进雾和景深里。焦点靠光和对焦来表达，不靠加框、加箭头。
4. **字不会"啪"地出现。** 文字从霜里浮出来、清晰起来；读的时候不动（标注等镜头停稳才出现）。
5. **动效有因果、不剪断。** 顺序是光先动 → 物体跟着动 → 文字最后清晰。3D 和网页文字之间不能出现硬切。

## 2. 光与材质

### 2.1 实测：我们 vs PV（`tools/lookstats.py`，本机 GPU）

| 画面 | 平均亮度 | 亮部 p95 | 边缘密度 | 清晰区占比 |
|---|---|---|---|---|
| **PV 29.5–33 s（5 帧平均）** | **0.79** | **0.913** | **4.95** | **2%** |
| 我们·入场落定 | 0.77 | 0.895 | 8.99 | 5% |
| 我们·首页 | 0.72 | 0.893 | 14.41 | 12% |
| 我们·浏览 | 0.78 | 0.896 | 10.45 | 18% |
| 我们·文件页 | 0.84 | 0.943 | 14.83 | 22% |

**怎么读这张表：** 平均亮度差不多，但**我们的画面细节和锐度是 PV 的 2–3 倍**，清晰的区域占了 5–22%，PV 只有一条约 2% 的对焦带。

**公平复测**（回应独立审查：PV 帧是 B 站压缩视频，我们的是无损截图，而且含网页文字）：把我们的帧隐藏全部网页层，只留场景，裁成 16:9，缩到 PV 的 1280×720，再用 JPEG 质量 70 压一遍，结果：

| 画面 | 平均亮度 | 边缘密度 |
|---|---|---|
| 首页（只有场景） | 0.71 | 19.2 |
| 浏览（只有场景） | 0.77 | 11.2 |
| PV | 0.79 | 4.95 |

差距不但没缩小，首页还更大。结论成立：场景本身太清楚、太碎，亮部也不够白。这就是"像 CG 方块"的量化原因。方法：`.codex-runtime/direction/tools/`（`fair.cjs` 截图，`lookstats.py` 计算）。

`focus%` 是**相对本帧最大值**的比例，只说明清晰区域有多集中，不是绝对锐度。判断锐度看边缘密度。

**目标（档案馆类画面）：** 平均亮度 0.80–0.84；p95 ≥ 0.91；边缘密度 ≤ 6；清晰区 ≤ 8%。文件页和内景另算，文字区不计入。

### 2.2 镜头与调色（改哪里：`scene/stage.ts` 的后期链）

| 项 | 现在 | 目标 |
|---|---|---|
| 色调映射 | ACES | 试 **AgX** 和 Neutral：AgX 高光过渡更柔，更接近 PV 的奶油白 |
| 曝光 | 静止时偏暗（首页 0.72） | 静止高调，+0.15–0.25 EV；文字区上方加雾，不靠压暗整个场景 |
| 景深 | 光圈小，大半个画面是清楚的 | 对焦带只落在焦点硬盘上；光圈约为现在的 2 倍；近处、远处都融进暖雾 |
| 雾 | 只有远雾 | 近雾 + 远雾，雾色就是背景的奶油色 |
| 光晕 | bloom 只在读盘时开 | 常开一层很淡的 **halation**：阈值高（≈0.85）、半径大、强度 0.15–0.25，只让高光"发出来" |
| 颗粒 | 无 | 色调映射之后加一层**静态**颗粒（固定图案，1–1.5% 亮度），像相纸的质地；镜头运动时可以顺带刷新。不做 24 fps 的动态颗粒：它和"有人读时不能有东西动""静止就停止渲染"冲突。手机不加 |
| 暗角 | 无 | 8–12%，暖色 |
| 选中 | 抬高 + 灯光 | 加 **移焦**（rack focus）：对焦面在 300–450 ms 内从旧焦点滑到新焦点 |

### 2.3 材质：只用五种

| 材质 | 用在 | 要点 |
|---|---|---|
| **霜 Frost** | 硬盘外壳、文件页盘面玻璃、内景地块 | 透射 0.85–0.9，粗糙 0.30–0.38；加一张很细的磨砂法线噪声，打散高光，去掉塑料感；衰减色比现在浅 |
| **象牙 Ivory** | 盘框、端盖、页面底色 | `#EEE6DA` 附近，粗糙 0.45，微弱 sheen；**禁止出现棕色、焦糖色** |
| **光 Light** | 蚀刻线、内芯、LED、读盘扫光 | 琥珀 `#FFB46B` 表示"可读、被点亮"；红 `#E0502A` 只表示攻击、拒绝、销毁 |
| **墨 Ink** | 网页里的文字 | 只出现在霜已经散开的地方 |
| **烟 Smoke** | 只用于 X-000 | 深色磨砂 `#2B2E31` 加红色蚀刻；全站唯一的暗色物体。红线在暗底上容易滑向"暗色霓虹"（`DESIGN.md` 的否决项），所以 L1 先出效果图给用户判断；不行就保持现在的黑色盘 |

**"木头感"的根因（文件页的盘框、选中的硬盘）：** 内芯是棕色 `0x806447`（`stage.ts`），隔着暖色衰减的磨砂外壳透出来，再加上盘框偏暖偏暗，读起来就是木头和纸板。改法：内芯换成浅陶瓷色（约 `#CDBFAE`），亮起来的时候靠内芯的自发光（琥珀色），不靠基色变暗变黄。

### 6.2 语法

**时长 token：**
- 微反馈 120–180 ms
- 标准 280 ms
- 慢 560 ms
- 场景 900–1300 ms

除了入场和内景导览，任何转场都不超过 1.4 s。

**曲线：**
- 空间运动：用现有的临界阻尼弹簧，三档：snappy ω=18、base ω=12、heavy ω=7。
- 透明度和模糊：入场用 `cubic-bezier(.16,1,.3,1)`（expo-out）；退场用 `cubic-bezier(.4,0,1,1)`，时长是入场的 0.7 倍。

**规则：**
1. **重叠，不排队。** 下一段在上一段完成 60–70% 时就开始；空等不超过 150 ms。
2. **3D 和网页不能硬切。** 每块网页面板都"挂"在一个 3D 物体或镜头上，从它的物体那里出来，回到它的物体那里去。
3. **可打断。** 转场途中任何输入都会改变弹簧目标，不排队等待。
4. **读的时候不动。** 文字出现之前，镜头必须已经停稳。
5. **运动模糊只给快速平移。** 强度最多是现在的一半，选择时不再整屏糊掉。

### 6.3 霜散开（全站的签名动作，替代黑条）

- **3D：** 盘面磨砂的粗糙度随一条扫线从 0.35 降到 0.04（`onBeforeCompile` 注入 `roughnessFactor`，透射采样随之变清）。扫线经过之处，蚀刻线亮一下。
- **网页：** 文字层盖一层 `backdrop-filter: blur(6px)`，遮罩是 `mask-image: linear-gradient(...)`，和 3D 扫线**同向、同进度**。文字本身从 `opacity .35` 升到 1。扫线经过时，标题下方的发丝线随之填满，末尾显示 `SHA-256 ✓`（这就是完整性校验，不再单独占时间）。
- **时长：** 打开 700 ms；关闭时霜从边缘回来，350 ms。

### 6.4 分镜（目标）

**T1 首访：** 0–6.0 指纹（不变）→ 6.0–6.6 位图结霜，退进白场（名字留着）→ 6.6–12.0 入场（PV 语法，保留）→ 12.0–12.8 镜头停稳在**首页构图**。首页构图的原则：
- 论点放在左侧的雾里，背后没有任何硬盘。
- 焦点是 4 个精选：从档案馆里升起，排成 01→04 一条线（像 PV 里档案被抽出来），从内部亮起来。
- 标注挂在每块硬盘下方，基线对齐，像展签。
- 标注在镜头停稳后从 01 到 04 依次淡入，间隔 80 ms。
- lookdev 做两版构图：A 只有 4 块；B 加上 YW-000（他本人）作为论点的锚点。由用户选。

## 7. 手机：画面不糊

### 7.1 为什么 v2 看起来糊（读的是 `src/casefile/mobile/scene.ts`）

1. `pixelRatio = Math.min(devicePixelRatio, 1.5)`：3 倍屏手机只渲染 1.5 倍，再被浏览器放大 2 倍，所以发软。
2. 帧率预算（第 136–138 行）一旦掉帧，就把像素比降到 1.0，而且**永远不再升回来**。降一次，之后一直是 3 倍放大。
3. 内景地块这类**承载信息的线稿**也画在 WebGL 里，跟着低分辨率一起糊。
4. 阴影用的是 1024 的 PCFSoft，在低像素比下边缘发虚。

### 7.2 规则

1. **信息用网页 / SVG，氛围用 WebGL。** 文字、标注、演示、内景地块的线稿，都用 DOM 或 SVG，靠 CSS 3D（由相机投影算出 `matrix3d`）贴到透视里，在原生像素比下渲染，任何屏幕都清楚。WebGL 只画档案馆这种"本来就该柔"的氛围。
2. **停下就变清楚。** 运动中用 1.25–1.5 倍渲染；停稳 250 ms 后补渲一帧 `min(dpr, 3)` 的高清帧，然后停止渲染（省电）。预算降下去的像素比，静止时要升回来。
3. **手机不开景深后期。** 景深在低分辨率缓冲上一做就糊。手机的景深靠雾和预先模糊的远景层来表达。
4. 用 MSAA（WebGL2 多重采样），不用 FXAA。不用实时软阴影，改用烘焙的接触阴影贴图。
5. **画布尽量小。** 只在需要 3D 的区域放 canvas，同样的成本就能用更高的像素比。

### 7.3 v2 视觉升级

v2 的方向（编辑式大字、右侧一弧硬盘做选择器、底部 Profile / Files / Contact）可以保留。要换掉的是：
- 用 §2 的霜和光替换现在灰扑扑的盒子；
- 文案和头衔跟桌面统一（v2 还是旧的 "Analyst & Engineer"、旧入场和自带的口号）；
- 选择器拖动时 60 fps，松手后补一帧高清。

**验收：**
- 执行会话可以自己证明的：
  - Playwright 手机视口（390×844，DPR 3），截图里文字和线稿边缘的过渡宽度 ≤ 1.5 设备像素（取一条水平线做亮度剖面来测）；
  - CDP `Network.emulateNetworkConditions`（下行 4 Mbps、上行 1 Mbps、RTT 100 ms），配合 `Emulation.setCPUThrottlingRate(4)`，首屏文字 ≤ 2.5 s；
  - 静止 1 s 后画布像素比回到 `min(dpr, 3)`。
- 需要用户在真机上确认的：iPhone（Safari）和中端 Android 各看一次，判断清不清楚、顺不顺。转场 ≥ 50 fps 的数字可以用 Safari 的 Web Inspector 读。

### L1 光与材质（`look.ts` 定稿值）

**改了什么：**
- 色调映射：ACES 保留。AgX 在这个场景里发灰，不采用。
- 曝光、景深：曝光 × 1.0；屏幕焦外半径 × 0.9、强度 × 2.6；再叠一层真实景深（光圈 0.00018，最大模糊 0.0055）。
- 光晕：常开 0.16，阈值 1.3，半径 0.55。阈值必须高于奶油色表面，否则整片发白，第 2 版就是这么失败的。
