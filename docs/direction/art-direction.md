# 第一部分 · 审美

## 0. 一句话

**这个网站是一台正在运转的精密安全设备。** 每块盘是一个密码模块（外壳、电路、安全芯片）；打开一份档案，就是在你的浏览器里真的解密它；一个机器在说话的界面，一直在用很小的字报告它正在做什么。光只表示密钥和权限在哪里流动。

用户给这份作品的三句话，是所有判断的终审：
- "清晰、克制、有科技感，可以是现实中不存在的科技感。"（10-06）
- "我是做网络安全的，这不是随随便便一个网站。"（10-06）
- "所谓视觉艺术，就是看到这个页面、这个动作的时候，就有舒服的感觉。"（10-09）

## A. 舒服从哪里来

"舒服"不是神秘的东西。它来自眼睛和大脑省力：知道往哪看，能预判接下来会发生什么，预判又被准确地兑现。生硬，就是这三件事里有一件断了。下面每条原则，都对应其中一种"省力"。

参考依据是用户最喜欢的莱因生命 PV（帧在 `.codex-runtime/design/pv/`，时间码用 PV 的秒数），图板见 `evidence/PV-missing-qualities.jpg` 和 `evidence/PV-transitions.jpg`。

### A1 · 眼睛永远有落点

- **为什么舒服：** 眼睛跳到哪里，要有东西接住。画面整体在动的时候，如果有几样东西一直不动，眼睛就以它们为参照，不用每一帧重新找。
- **PV 怎么做：** 四角的机构抬头、准星角标、"SELECTING FILES" 的文字位置，从 27 s 到 31 s 一直不动；整片档案在它们下面滑过、减速，最后把目标**送进准星**（30.9 s）。是世界来就主角，不是主角满屏跑。
- **我们怎么用：** 每个转场先定"锚"：什么不动（抬头、准星、标签位置、正在读的那行字）。镜头和物件围绕锚运动。
- **违反时的样子：** 转场之后要重新找刚才在看的东西；文字换了位置；准星跟着物件跑。

### A2 · 动、停、动：有呼吸的节奏

- **为什么舒服：** 一直在动让人累，动完立刻停死让人觉得被撞了一下。快进、慢落、停住，留给眼睛"看清"的时间，然后再开始下一拍。
- **PV 怎么做：** 档案从白里快速滑入，速度用运动模糊表达（27.1–28.1 s）；越来越慢，落定后**停 1.6 s**（31.3–32.9 s），这时画面是清楚的；然后才开始下一个动作。
- **我们怎么用：**
  - 速度只出现在动的时候，停的时候必须清楚（和 A9 一致）；
  - 每个场景转换后都有一个"停住看清"的拍子，长度和信息量相称：一个标题约 0.6 s，一个物件约 1–1.6 s；
  - 曲线是快进慢落，不用匀速，不用弹跳。
- **违反时的样子：** 东西一直在漂；动画在全速时被硬停；连续几个动作之间没有喘气；动的时候反而看不清要看的东西。

### A3 · 主角连续，换的是世界

- **为什么舒服：** 大脑跟踪的是"那个东西"。只要它一直在画面里，周围怎么变都不会迷路；一刀切到新画面，就得重新建立"我在看什么"。
- **PV 怎么做：** 选中的档案升起，周围整片场面**化成纸色**退场，最后只剩它（33.1–33.9 s）。主角没有被切走，是世界让开了。
- **我们怎么用：** 场景转换的默认做法是"让世界退场"（化成纸色、淡出、收拢），而不是淡出整个画面再淡入下一个。主角（一块盘、一行字、一个准星）从上一个场景带进下一个场景。
- **违反时的样子：** 整屏淡入淡出；页面一帧出现或消失；打开一份档案时盘从画面里消失，换成一个不相干的页面。

### A4 · 换一种画法，而不是换一个画面

- **为什么舒服：** 同一个东西换一种表现方式（实物 → 线稿 → 实物），眼睛知道它还是它，但获得了新的信息层。这是转场里最有创意、也最"高级"的一类：变化很大，却毫不费力。
- **PV 怎么做：** 镜头推到外壳填满屏幕，外壳本身成了画框（42 s）；外壳退成**细线**，里面的零件以实体浮出来（43 s）。
- **我们怎么用：**
  - 进入一块盘时，外壳退成线稿，内部以实体出现；
  - 内景六站本来就是线稿世界：从实物盘到线稿内景，应该是"换画法"，不是交叉溶解；
  - 演示的画布就是那一层部件的线稿。
- **违反时的样子：** 两种风格的画面硬拼在一起（实物画面突然切成扁平 UI）；或者只做溶解，两个画面在中间糊成一片。

### A5 · 字踩在动作的节拍上

- **为什么舒服：** 画面落定的那一刻，正是眼睛准备读字的时候。字在这时打出、打完，读和看是同一拍；字早到会抢镜，晚到会让人干等。
- **PV 怎么做：** "SELECTING FILES" 在镜头减速时逐字打出，"FILE NUMBER: X-001" 在档案升到位时换上（30.7–31.1 s），"CONFIDENTIALITY: BUSINESS USE" 跟着测量线一起出现（35–37 s）。
- **我们怎么用：** 每段状态字的开始和结束都对齐一个动作节点（减速开始、落定、校验完成）。解密的标签行在最后一块解开的同时出现。
- **违反时的样子：** 字先冒出来、画面还在跑；画面停了，字还没来；一大段字整块弹出来。

### A6 · 一台在运转的机器在说话（设定感）

- **为什么舒服：** 画面像是"一个系统在工作"，而不是"一张网页在展示"，这种可信的设定让人愿意相信、愿意看下去。现实里不存在、但内部逻辑自洽的科技，就是用户说的"现实不存在的科技感"。
- **PV 怎么做：** 机构抬头和 "POWERED BY" 常驻四角；系统用极小的等宽字报告状态，配细引线、角标、刻度。
- **我们怎么用：**
  - 一层"操作系统"常驻：抬头、细框线、角标、刻度；
  - 它报告的都是**真实发生的事**：会话密钥、块号、标签校验、权限、指纹哈希。口吻是机器的，内容是真的。这一点我们比 PV 更进一步，也正好是安全作品集该有的诚实；
  - 等宽字只给这层"机器的话"和数据。
- **违反时的样子：** 装饰性的假 HUD（乱码、假进度条、无意义的十六进制）；一个普通网页风格的页面（Codex 手机版的主要问题之一）。

### A7 · 物件有内部，可以被拆开

- **为什么舒服：** 一个东西被打开、拆解，会给人"看到了真相"的满足感。内部的结构就是内容。
- **PV 怎么做：** 磨砂外壳里隐约看得见机构（37–39 s），打开后零件一层层分离、放大，成为爆炸图（41–45 s）。
- **我们怎么用：** 盘的内部就是那个项目的系统。打开一份档案，就是把这块盘拆开：每一层部件是系统的一个组成部分，用引线标注。因为是一层层叠的结构，竖向滚动正好对应"拆开"的方向（§9）。
- **违反时的样子：** 档案只是一张卡片、一页文字；"一摞盘"这种只从外面看的排列（用户 10-09 否：没有质感）。

### A8 · 尺度旅程

- **为什么舒服：** 从宏观推到微观再拉回来，给人"这个世界有纵深"的感觉；每换一个尺度，都看到新的细节。
- **PV 怎么做：** 平面标志 → 一整片档案 → 一个物件 → 内部零件 → 带刻度的网格空间（11–45 s）。
- **我们怎么用：** 入场是一整片档案馆，收到一块盘，钻进安全芯片，再展开成部件，最后停在带刻度的平面上。每次换尺度都用 A3 或 A4 衔接。
- **违反时的样子：** 一直停在同一个尺度上（只有"产品照"是静的）；尺度跳了却没有衔接。

### A9 · 清晰

- **为什么舒服：** 承载信息的东西看不清，眼睛会一直使劲。清晰本身就是"专业"的信号，对安全行业的读者尤其如此。
- **我们怎么用：** 不用模糊做氛围；远处用轻微的色调衰减推远，不糊掉。运动模糊只在快速运动时出现，停下必须清楚。手机上静止后补渲一帧高分辨率画面（§9）。
- **违反时的样子：** 一片暖雾、光晕、景深糊（用户 10-06 否 v1："太亮、太糊"）。

### A10 · 冷中一点热

- **为什么舒服：** 大面积的中性（象牙、纸、玻璃、钛）让画面安静，一小处饱和的热色把视线钉住。热色越少，越有力。
- **PV 怎么做：** 灰白玻璃的零件里，一道橙色（41–45 s）。
- **我们怎么用：** 物件里只有一处真正的热点：安全芯片和密钥通路。网页里的橄榄色表示"可读 / 已验证"，红色表示攻击、拒绝、销毁。热色永远是信息，不是装饰。（用户 10-09：这一条"部分对"，具体色值在样片里定。）
- **违反时的样子：** 处处暖色；热色当装饰随便用。

### A11 · 物理上站得住

- **为什么舒服：** 物件遵守物理，大脑才会把它当真的东西看。一次穿模就会让整个世界变假。
- **我们怎么用：** 盘永远在自己的槽里，或者在打开机构的手里；在场里只沿自己的槽上下移动，不横穿别的盘，不悬空；要横移，先完全升出场面（用户 10-08 否阶梯版："飞在空中还穿模"）。
- **违反时的样子：** 悬空、穿插、无依托的漂浮。

### A12 · 每个意象都是真的安全机制

- **为什么舒服：** 对懂行的读者，"真的"本身就是美感；对不懂行的读者，真实的东西比装饰更有分量。
- **我们怎么用：** 解密就是真解密（AES-256-GCM、真密文、真校验）；指纹就是浏览器真实的指纹；密钥是真的会话密钥。提出任何视觉比喻之前，先说出它代表哪个真实机制；说不出，就不用（用户 10-06 否"霜散开"）。
- **违反时的样子：** 和安全无关的比喻（霜、灯笼、玻璃变清）；假数据。

## B. 怎么做审美判断

- **在真实设备上看，按真实速度看。** 先 1 倍速看三遍凭感觉，再逐帧找原因。手机效果只在手机上判断。
- **一次只改一件事，做 A/B。** 关键转场给两到三个版本（节奏、曲线、停顿不同），由用户凭感觉挑。挑出来的那个就是标准，写回这份总纲。
- **删掉测试。** 去掉一个效果，如果什么都没少，它就是装饰，删。
- **眯眼测试。** 眯着眼看，一帧里应该只有一个最亮、最清楚的焦点。
- **硬切测试。** 用实时录屏逐帧看：画面里任何东西在一帧之内出现或消失，就是硬切，除非它是刻意的（PV 里也几乎没有）。
- **讲得出原则。** 每个效果都能说出它服务哪条 A 原则；说不出，就不该在那里。

### 2.2 首页的四块精选（`?shelf=1`）

四块盘的外壳在首页变成**透明**，露出内部电路，电路线被点亮（`briefEtch 0.75`）；其余档案保持磨砂，内发光降到 15%。意思是：这四份对你开放，其余的锁着（A12）。

### 2.3 实测

规范：16:9、1280×720、JPEG 70，工具是 `tools/lookstats.py`。

| 文件页 | 0.84 / 0.94 / 15.2 | 0.85 / 0.95 / 14.2 | 0.85 / 0.95 / 16.1 |

**R2 基准（10-08，首页重做之后；P2 的验收用这一组）：** 方法固定为 `tools/fair.cjs`（1440×900，只拍场景）+ `tools/fairstats.py`（居中裁 16:9 → 1280×720 → JPEG 70 → `lookstats.py`）。

| 画面 | 亮度 / 高光 p95 / 边缘 |
|---|---|
| 首页 | 0.802 / 0.885 / 14.9 |
| 浏览 | 0.786 / 0.898 / 11.2 |

首页比上表的 v2 亮 0.02、边缘少 3：镜头更广，画面里纸色的场面更多。这是构图变化，不是光变了。

### 2.4 原版里的一个真 bug（已在 P1 修）

盘面电路的贴图平面（`BOARD_Z`）和精密模型的电路板正面完全共面，镜头推近时电路板盖住电路线。修法：蚀刻材质加 `polygonOffset`（factor −2，units −4）。

## 3. 解密：全站的签名动作（`?motion=1`，代码 `ui/cipher.ts`；服务 A12、A5）

### 3.1 机制（真的，不是动画假装）

- 每个会话在浏览器里生成一把 **AES-256-GCM** 会话密钥（WebCrypto，不可导出，不离开这个标签页）。
- 打开一份档案时，用它把页面上看得到的文字**真的加密一次**，每次用新的 96 位 IV。先以**真实密文**的比特显示出来，再逐块解密，最后**真的解密一遍并验证 GCM 标签**。
- **16 个字符 = 一个块**，对应 AES 的 16 字节分组。按阅读顺序，也就是计数器（CTR）顺序解密。
- 关闭档案时**用新的 IV 重新加密**，所以回来时看到的密文和刚才的不一样。同一明文，两次密文不同。
- 安全背景的读者可以在 devtools 里看到这是真的。这本身就是作品集的一部分。

### 3.2 视觉

| 元素 | 规格 |
|---|---|
| 文字的密文 | 每行文字变成一条数据带：正文 2 行、标题 3 行方形比特格，正文格 2 px、标题格约字号的 8.5%。1 比特用墨色 50%，0 比特用 5%，垂直居中在行高上 |
| 轮到的块 | 比特变成橄榄色，下方出现 1 px 橄榄色细线（意思是"变成可读"），随后字母在 120 ms 内显出 |
| 盘面（演示） | 8 × 5 个 AES 块，每块是一个 16 × 8 比特的小芯片，四周留白，像一张内存映像；按计数器顺序逐块解密，轮到的块出现橄榄色描边 |
| 标签行 | 一根 72 px 的橄榄色发丝线填满，接着显示 `AES-256-GCM · N blocks · tag verified`；校验失败时变红 `tag check failed`。和最后一块同时落地（A5） |
| 时长 | 点击后 0.3 s 页面出现（此时盘还在转身）；盘面解密 420 ms；文字在盘面开始 110 ms 后解密，共 560 ms；**约 1.1 s 可读** |
| 关闭 | 和打开对称（10-08 改）：盘**先保持朝向读者**，文字和盘面一起按"最后一块先"匀速重新加密（文字 260 ms、盘面 230 ms）；加密完成七成（180 ms）时盘开始转身，加密完页面淡出 220 ms，**淡完才移除**（A3）。关档用的密文（新 IV、比特图）在阅读时就趁空闲备好，所以按下 Esc 到第一块开始 ≤ 100 ms；窗口尺寸一变就作废重备 |

### 3.3 生产实现要点（给执行会话）

原型是在 DOM 上临时把文本节点拆成块，用完把**原节点**放回去。**P2 沿用这个做法**（改动小、已验证），条件是可打断：关闭、下一份、后退时先同步还原，再让 React 卸载。以后文件页的结构变得更动态，再改成 `<Cipher>` 组件。

- 手机（宽 < 900 px 或粗指针）：只解密文字；盘面不叠 8 × 5 的块网格（§9）。
- reduced-motion：直接显示明文，标签行照样显示。
- 文本不足 16 个字符也算一块。
- 中文和多字节字符按字符切块。块和字节的对应是近似的，这一点在注释里说明，不能对用户宣称逐字节对应。

| # | 转场 | 原版 | v2 | 说明 |
|---|---|---|---|---|
| T4 | 打开文件（到能读） | 3.4 s（先打哈希、再退黑条） | **约 1.2 s** | 盘还在转身时页面就进来了 |
| T5 | 关闭 | 2.8 s | 重新加密到七成时盘才转身 | 旧版是盘一边转身、页面一边加密，演示平铺在原地对不上，页面淡到一半被拿掉（违反 A3）。关档时还有一处原有的"整页闪一帧"，P2 在查 |
| T6 | 下一份 | 4.7 s，中途还闪浏览面板 | **约 1.9 s 能读** | 途中隐藏浏览 HUD；运动模糊降到 0.3 倍 |

**T7 门：**

| 时间 | 发生什么 |
|---|---|
| 0–0.9 s | 盘抬起、转身 |
| 0.9 s 起 | 密钥的光从安全芯片沿电路跑出 |
| 1.2 s 起 | 盘立起正对镜头，**磨砂外壳向上滑开**，露出电路板 |
| 1.2–3.4 s | 电路保持点亮，镜头沿着亮着的电路推到芯片，芯片随之亮起 |
| 约 3.4–3.9 s | 交叉淡化进内景：内景的芯片接着盘上的芯片。下一步改成"换画法"（A4）：盘的电路退成线稿，正好就是内景的线 |
| 约 5.2 s | 第一站 |

**语法：**
- 每个转场先定锚（A1）：什么不动。
- 节奏是动、停、动（A2）：微反馈 120–180 ms、标准 280 ms、慢 560 ms、场景 900–1300 ms；场景转换之后要有"停住看清"的一拍。除了入场和内景导览，任何转场都不超过 1.4 s。
- 曲线快进慢落：空间运动用临界阻尼弹簧，网页用 `cubic-bezier(.25,.1,.25,1)` 一类均匀的曲线。不用前两帧就到八成的曲线，它在实时里等于硬切。
- 换场景时让世界退场、主角留下（A3）；能"换画法"就不溶解（A4）。
- 字踩节拍（A5）。
- 后一段在前一段完成 60–70% 时就开始，空等不超过 150 ms。
- 转场可以被打断；有人读的时候画面不动。

## 9. 手机（10-09 定方向：C + D，入场之后一次只有一件主角）

**方向（用户 10-09 认可）：** 手机不是把桌面换个镜头。手机访客主要是招聘方快速浏览，以及用户线下当面拿手机展示。所以：
- 整片档案馆只在入场出现一次（A8 的起点）；
- 之后**一次只有一件主角**：一块盘，近、大、清楚；
- **竖向滚动就是时间轴**：盘升起、外壳退成线稿、内部一层层拆开（A4、A7）；手指在操作这个物件，不是在点播放；
- **操作系统层常驻**（A6），报告真实发生的事；
- 有一个"展示模式"：点一下，四个精选自动走完一遍，约 40 秒，对方随时可以接手。

**否掉的：**
- Codex 的手机版（标签栏 + 目录 + 轮播，3D 当装饰；见 `docs/mobile-audit-2026-10-02.md`，代码在 `feat/mobile-v2`）。它当成导航问题来解，3D 失去了角色，还多出一套身份（违反 A6）。保留它的一条正确判断：演示是主要内容，不折叠。
- "一摞盘"浏览全部档案（用户 10-09：没有质感，违反 A7）。

**样片（10-09 做了，被否）：** `.codex-runtime/lookdev2/phone.html`（A/B/C 三版）。用户评价：三版都非常生硬，和网页版完全比不了，也看不出三种设计；只有 C 的**概念**（世界退场、主角留下）可以留。原因，记下来别再犯：
- 样片从零写，扔掉了网页版质感的真实来源：指纹页、按 PV 逐帧复原的入场（浪 + 镜头甩动、按画面速度的运动模糊、曝光回落、对焦带）、所有物件的弹簧物理。换成了自己编的一段接一段的动作（白闪、滑入、呼吸），不重叠、没重量。
- 三个版本只改了时长数字，编排一样，所以看不出区别。版本之间要差在编排，不是数字。
- 即使是原型，也必须朝最终效果去做；"先展示概念"不成立，用户是凭感觉判断的。

**现状（10-09 实录，390×844）：** 正式版在手机上，指纹页和入场的质感是在的；首页是文字压在淡掉的阵列上，是最弱的一段。

**下一步：** 手机 native 的视角和网页由用户在新会话里重新设计（10-10 决定）。本节的方向（C + D）和否掉的清单仍有效，样片的做法作废。

**清晰度（10-09 实测，A9）：** 手机一开始是中档（像素比 1.5），几秒内就降到低档（像素比 1）。在 3 倍屏上，3D 只按屏幕像素的 1/3 渲染再拉伸，所有边缘都是放大糊。原型 `?crisp=1` 的做法：
- 手机上场面没人动时**静止**；
- 静止约 8 帧后按 2.25 倍像素比**补渲一帧**，之后不再重复渲染，直到有东西动；
- 一动就回到档位的像素比保帧率。静止判定带回滞：每帧变化低于肉眼阈值才算静止，补渲之后累计偏移超过约 0.7 像素才重画；
- 静止时完全不渲染，也省电。

对比图：`evidence/R3-phone-crisp-crop.png`。**风险：** 补渲那一帧在弱手机上可能要一两百毫秒，要真机确认。

**其他：**
- 信息用网页 / SVG 渲染，氛围用 WebGL；文字永远落在纸色底上，不压在 3D 上读。
- 手机不做景深后期。
- 手机上的解密只做文字部分，盘面不叠块网格（§3.3）。
