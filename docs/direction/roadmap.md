## 0. 这个网站要做成什么

**一句话：** 让招聘方在 10 秒内知道 Yaoting 是谁、做过什么，愿意往下看、来联系。并且在他当面拿手机给人看时，让对方记住。

**时间是硬约束。** 他 2027 年 4 月起可以全职入职。加拿大应届岗位的招聘季大约是 **2026 年 10 月到 2027 年 2 月**，也就是现在。所以排序原则是：**先让带人进来的路走通，再打磨质感。** 质感不是不重要，而是一个招聘方根本没进门时，质感救不了。

**访客是谁、从哪来：**

| 访客 | 从哪来 | 要什么 | 现在的体验 |
|---|---|---|---|
| 招聘方 / HR 初筛 | 简历 PDF、LinkedIn、邮件里的链接 | 30–90 秒看懂：头衔、经历、能不能用 | ⚠️ 首访要约 13 s 才到首页论点（简历链接等网站做完由用户自己加） |
| 用人经理 / 面试官 | 同上，会点进项目 | 看深度：做了什么、怎么做、证据 | ✅ 项目档案有真演示、数字有来源。⚠️ 从链接直接点进项目时，首访要先放完整个入场 |
| 当面展示 | 他自己的手机 | 一两分钟内，对方留下印象 | ❌ 手机是最弱的一环，**用户现在没法拿它去分享**（首页四块精选盘不在画面里，下半屏只是一片淡掉的阵列） |
| 机器读者 | LinkedIn 预览、AI 摘要、无 WebGL 设备 | 读得出纯文本简历 | ✅ 每个页面都有预渲染的纯文本、分享卡片、站点地图 |

## 2. 还缺什么（诊断）

按影响排序。每条都写了证据。

1. **手机拿不出手。** 用户的原话："手机的网页没做好我都没办法拿去跟别人分享"。10-09 在 390×844 上实录：指纹页和入场的质感在；首页上半屏是文字，四块精选盘根本不在画面里，下半屏只是一片淡掉的阵列；浏览页可用；打开档案、关档、Index、联系在手机上还没系统走过。
2. **第一面还没定。** 入场多长，取决于我们想让人第一眼看到什么，这是美术和叙事的决定，不是性能参数。从链接直接点进项目的首访，现在也要先看完整个入场（`CasefileApp.tsx`：是否放入场只看 `yw.entry` 和 `?intro`，不看路径），这和"第一面看到什么"是同一个问题，一起定。
3. **我们是在盲飞。** 网站没有任何访问统计：不知道有多少人来、从哪来、在指纹页跳过还是离开、看了哪几个档案。首访约 13 秒（本机桌面高画质实测 13.0–13.8 s；手机和低端机没量过，只会更慢）到底劝退了多少人，只能猜。
   - 难点：V-FILE 的隐私统计（`PrivacyStat.tsx`）现在写着 "0 trackers · 0 cookies"。它只数第三方请求，同源的统计不会被数到。那样数字仍是 0，但已经不是实话，违反 A6（机器只说真话）。所以加统计就必须同时改 V-FILE，如实写出来。
4. **手机的新设计还没有。** 已有两次样片被否，用户在新会话里重新设计（`art-direction.md` §9）。保底（第 1 条）先于新设计。
5. **桌面还差"拆开"那一层质感。** A4（换画法）和 A7（物件有内部）只在门里做到一部分：盘没有内部部件，打开档案时外壳只是变清，门到内景是交叉淡化。
6. **性能还有已知的一处卡顿。** 首页出现时主线程卡 170–250 ms，会压缩上场节奏。指纹页开头的 270–360 ms 主要是第一次建 WebGL，已接受为下限。
7. **内容会过期，而且有两份源。** 简历系统和 `entries.ts` 各写一份。Coast Capital 是正在进行的 co-op，结束时两边都要改。没有机制保证两边一致，只有 `numbers.test.ts` 管数字来源。
8. **无障碍没审过。** 有减弱动效和纯文本兜底，但没做过系统检查：操作系统层大量 8–9 px 的等宽小字、对比度、读屏顺序、全键盘路径。
9. **收尾欠账。** 定稿规则没写回 `DESIGN.md`（`handoff.md` S7）；评审回路（`review-log.md`）停在 10-05；还有 8 个旧分支、4 个旧工作副本。

## 3. 阶段

### P3 · 手机保底 + 简单统计（现在做）

**目标：** 用户可以放心把网站链接发给别人，或当面拿手机给人看：手机上主路径完整、没有坏的、读得清，首页能看到他是谁和四个精选。**保底不是新设计**：不改动效编排，不预设 M 的方向，只修"拿不出手"的地方。

| # | 做什么 | 验收 |
|---|---|---|
| P3.1 | **手机审查**：在一台真手机和 390×844 模拟上，把主路径完整走一遍（指纹页 → 入场 → 首页 → 浏览 → 打开精选档案 → 演示 → 关档 → Index → 简历 / 联系），每一屏截图、录实时视频，列出所有"拿不出手"的问题，按严重程度排。纯取证，不做设计 | 一份问题清单，每条带截图或视频时间点，用户过目确认范围 |
| P3.2 | **按清单修**。已知必修：首页四块精选盘要在画面里、和文字不打架；文字永远落在纸色底上；小字（操作系统层 8–9 px 等宽字）读得清，对比度 ≥ 4.5:1 | 清单逐条复验；用户在自己手机上走一遍，愿意拿去分享 |
| P3.3 | **简单统计**：Vercel Web Analytics，只记页面访问和来源（免费档就有，同源、无 cookie），不做自定义事件，不自建接口。V-FILE 的 "0 trackers · 0 cookies" 同时如实改写，例如 "1 first-party counter · 0 trackers · 0 cookies"，并一句话说明记了什么 | 生产环境能看到访问；V-FILE 写的和实际网络请求一致 |
| P3.4 | 走一遍转化路径：邮件、LinkedIn、简历下载都点得通；LinkedIn 分享预览（标题、描述、卡片图）对；X-000 的红队游戏在生产环境能用（接口密钥、限流）。`api/contact.ts` 前端已经不用了，确认后连同 `src/server/contact.ts`、它的测试和 Vercel 里对应的邮件服务密钥一起删掉 | 每项留证据（截图或请求记录） |

**为什么先做：** 网站只有被分享才有用，而现在用户自己都不愿意分享手机版。

### M · 手机 native（用户的新会话）

由用户在新会话里重新设计视角和网页。仍然有效的输入：`art-direction.md` §9 的方向（C + D）、否掉的清单和样片作废的三条原因，以及 §A 的审美原则。

- 和"第一面"（§2 第 2 条）一起定：入场多长、深链接首访怎么进，都是"第一眼让人看到什么"的决定，手机和桌面要一致。
- P3 的保底会被新设计替换，所以保底只做必要的修复，不在上面做精细打磨。
- P5 的"静止时补渲一帧"清晰度方案要真机确认。
- 和桌面共用的东西（真引擎、指纹页、入场、解密）改动时要两边一起看。

### P4 · 桌面质感："拆开"这一层

**前提：** P4 成本高、对招聘的直接价值低于 P3。动工前看一眼 P3.3 的访问数据：如果几乎没人打开档案页，P4 往后排，先做 P5、P6。

**目标：** 补齐 A4（换画法）和 A7（物件有内部），让"打开一份档案"从"盘转过来、变清"升级为"外壳退成线稿、内部一层层浮出、演示发生在部件上"。

| # | 做什么 |
|---|---|
| P4.1 | 用 Blender 建盘的内部部件：安全芯片、走线层、固定件。部件要对应真实的安全机制（A12） |
| P4.2 | 打开档案：外壳退成线稿，内部部件分层浮出（爆炸视图），演示落在对应部件上 |
| P4.3 | 门到内景改成"换画法"：盘上的电路退成线稿，正好就是内景的线，替换现在的交叉淡化 |
| P4.4 | 指纹页的退场、X-000 效果图、演示界面的"亮线"改法 |

每一项先出原型。原型必须朝最终效果做，用户在真机上凭感觉裁定，再写执行单交给 Sonnet。

### P5 · 性能与稳定

| # | 做什么 |
|---|---|
| P5.1 | 首页出现时 170–250 ms 的长任务拆掉 |
| P5.2 | 拆包：最大的包 577 kB（文件名叫 RoundedBoxGeometry，实际装着 three 的大部分），看能不能按需加载，或把首页用不到的部分推迟 |
| P5.3 | 低端手机：静止时补渲一帧高清的成本，以及降档时机，真机实测（和手机线一起） |

### P6 · 收尾

| # | 做什么 |
|---|---|
| P6.1 | 无障碍检查：读屏顺序、全键盘走一遍、其余对比度（小字已在 P3.2 处理），修到 WCAG AA |
| P6.2 | 网站做完后，用户自己给简历加网站链接（简历系统里是已经投出去的版本，现在不动）。内容同步：简历系统和 `entries.ts` 之间的对照检查（一个脚本或测试），Coast Capital 结束时的更新清单 |
| P6.3 | 把定稿规则写回 `DESIGN.md`；跑一轮评审，记进 `review-log.md` |
| P6.4 | 清理旧分支和工作副本。**删除前先盘点**：每个分支用 `git cherry main <分支>` 和 `git diff main <分支> --stat` 看有没有 main 里没有的内容，每个工作副本看 `git status`。已知：`.codex-runtime/lookdev2` 有 19 个没提交的文件（手机清晰度的原型）；`claude/nifty-dijkstra-acqxu3` 和 `lookdev/r1` 各有 13 个提交不是逐个进的 main（大概是压缩合并，要确认）；`C:/Users/User/.codex-account2/worktrees/...` 下还有一个工作副本；远端分支也要一起列。先打标签或导出补丁存档，清单交用户确认后才删。`feat/mobile-v2` 等手机线定了再说 |

## 4. 顺序

```
现在 ──► P3 手机保底 + 简单统计 ──► P4 桌面质感（原型 → 用户挑 → 执行）──► P6 收尾
                │
                └─ M 手机 native + "第一面"（用户新会话，之后替换保底）
                                    P5 性能穿插，和 M、P4 一起验
```

- P3.1 审查是纯取证，可以马上做；清单经用户确认后写执行单交给 Sonnet 修。
- P3.3 统计和 P3.4 走查不依赖任何美术决定，可以和 P3.1 同时做。
- P5.3 和手机线绑在一起，不单独排。
