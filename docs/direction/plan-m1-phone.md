## 0. 目标与非目标

**目标：** 用户能把 yaotingw.com 发给任何人，或者当面掏出手机演示。在竖屏手机上：
1. 画面和原型片一致：同一个准星、同样的弹簧、同样的打开转场、真解密；
2. 每一步都能用手指操作：按住指纹进入、上滑换档案、点开、读完、返回、Index、联系、简历；
3. 任何手机都流畅、清楚：手机上**不跑整片实时 3D**；
4. 内容完整：每份档案都能打开、读到全部内容、看到它的演示；
5. 没有一处坏的、读不清的、硬切的。

**非目标：**
- 桌面版的任何变化。桌面必须和 `main` 一模一样（验收 E8）；
- 访问统计、V-FILE 文案改动（路线图 P3.3，另做）；
- 桌面才有的功能：粉碎（shred）、图例滤镜、悬停标签、UEBA 告警；
- 横屏手机的完整体验：只显示一张纸面提示加可读索引；
- 平板：宽度 ≥ 900 px 的设备仍走桌面版；
- 任何没在 §7 列出、也没被用户批准的新文案。

## 2. 架构（PM 定，执行不改）

**一句话：** 画面全部在本机 GPU 上用真引擎预先渲好（"烘焙"），手机只负责摆放图片、播放短片和画网页层。

```
烘焙（本机，离线）                         手机（运行时）
真引擎 + 导演 ──▶ 静帧 .webp (3x)  ──┐
             ──▶ 短片 .mp4  (2x)  ──┼──▶ public/phone/  ──▶ 舞台：图 ↔ 短片 无缝交接
             ──▶ 每帧元数据 .json ──┘     manifest.json      网页层：准星、纸面、文字、演示
```

**2.1 母版画布：** 390 × 866 css px。静帧 3 倍（1170 × 2598），短片 2 倍（780 × 1732）。运行时按屏幕宽度等比缩放（`s = 屏宽 / 390`），顶端对齐，多出的高度从底部裁掉（底部本来就在纸面板下面）。网页层的坐标（准星框、盘面四角）都存在母版坐标里，运行时乘以 `s`。

**2.2 资产（全部由一条命令 `npm run phone:bake` 生成，可重复）：**

| 资产 | 内容 | 格式 |
|---|---|---|
| `entrance.mp4` | 入场的浪（原样），接上推近到 YW-000 封面。约 5.3 s | 2x，H.264 |
| `stop-<id>.webp` | 每份档案停在准星里的静帧：盘升起、外壳变清、其余灯退后。**每个条目都要有**，不止 5 份精选 | 3x |
| `pan-<a>-<b>.mp4` | 精选之间的平移，前后两个方向都要：YW-000 ↔ X-001 ↔ SR-01 ↔ SR-02 ↔ X-009，共 8 段 | 2x |
| `open-<id>.mp4` / `close-<id>.mp4` | 每个条目的开、关档（关档的时间线是独立渲的，不是倒放视频） | 2x |
| `window-<id>.webp` | 开档最后一帧：盘面铺满屏宽 | 3x |
| `door-YW-000.mp4` | 主档案的门：盘立起、盖板滑开、推到芯片 | 2x |
| `manifest.json` | 每个资产的文件名、帧数、帧率、准星框；开、关、门三种短片要有每一帧的盘面四角坐标（网页层按这个对齐，A1）；芯片中心位置；内容哈希 | — |

**交接规则：** 图到短片：等短片第一帧真的画出来（`requestVideoFrameCallback`）再隐藏图。短片到图：最后一帧和静帧是同一画面，用 120 ms 交叉淡化，把"动的时候略软、停下变清楚"的差别藏住。任何时候都不能露出空白或黑帧。

**2.3 运行时（全新的手机外壳，不碰桌面代码）：**
- `PhoneApp`：竖屏、宽度小于 900、触屏的设备才启用。它**不加载** three.js，也不加载桌面引擎；只有打开 YW-000 内景时才可能加载（见 §3 的 H6）。
- **舞台：** 管理图片和短片的叠放、预加载、交接；时钟一律跟着短片的媒体时间走，没在播片时跟应用时钟走。网页层的每一个动画都从这个时钟取值，**不用 CSS transition**。
- **状态机：** 指纹 → 入场 → 封面 → 浏览各站 ↔ 档案页；另有 Index、联系两层。URL 同步：`/` 和 `/projects/:slug`。返回键和 iOS 边缘返回手势都等于关档。
- **手势：** 竖向滑动超过阈值（约 12 px）就立刻开始播平移片；播放中再滑一次只排队一次；点"Open"或点盘就打开。浏览时禁止整页滚动和下拉刷新。
- **降级：** 减弱动效时，短片换成 150 ms 交叉淡化。短片加载失败也用交叉淡化。弱网时先显示静帧，后台再加载短片。没有 JS 时，预渲染的纯文本页照旧可用。

## 4. 阶段与工作包

每个工作包由**一个**执行子代理完成，在 `phone/p3` 上本地提交（作者 `JoKFA <felixwang1222@gmail.com>`，任何地方都不写 AI 署名）。做完交一份证据清单（命令和真实输出、截图或录屏路径）。PM 看过证据，再派**另一个**子代理按验收条逐条复验。复验不过就返工，不进入下一包。

### P0 · 探路（只做最小页面，回答 H2–H6）
- **P0.1 烘焙最小集：** 封面静帧、X-001 静帧、平移 YW-000→X-001、X-001 的开档短片、窗口静帧，外加 manifest（含开档每帧四角）。
- **P0.2 最小舞台页**（临时入口 `?phone-spike`）：封面 → 滑动 → X-001 → 点 Open → 窗口，叠上准星四点。
- **P0.3 实测：** Chromium 和 WebKit 各录一遍实时视频（60 fps）；扫描交接处有没有白帧、黑帧、硬切；查四角对齐误差；记各资产体积；五种屏幕尺寸各截一张；内景在降速 4 倍时的帧时间。
- **出口：** 一张结果表，每条假设标 ✅ 或 ❌，附证据。有 ❌ 的话，PM 改架构后再往下走。

### P1 · 烘焙流水线（生产版）
- 导演从 `lab.ts` 提炼成 `src/casefile/phone/bake/`（只在 `?bake` 下加载），**时间线和数值不改**（就是原型片那一版）；
- `npm run phone:bake`：起服务器、渲染 §2.2 的全部资产、ffmpeg 编码（H.264 yuv420p、faststart；静帧 WebP）、写 manifest、检查体积预算（超了就报错）；
- 引擎里的实验钩子保留，但要整理成一个有类型、有注释的 `labHooks`；不设时零开销（验收 E8）。
- **验收：** 全部资产生成；每个"短片末帧 vs 对应静帧"的像素差 < 2%（缩到同一尺寸后的平均绝对差）；所有短片扫描都没有硬切；重复跑两次，manifest 哈希一致。

### P2 · 手机外壳与浏览
- `PhoneApp`、启用条件、舞台、时钟、状态机、手势、URL、降级（§2.3）；
- 封面和五站：纸面、面板、准星、真解密（沿用原型的按块解密，代码搬进 `phone/cipherLine.ts`）、刻度 `00–04`（点刻度直接跳到那一站）；
- 顶栏：名字、Index、Contact。
- **验收：** 原型片 0–13 s 那一段在真页面上用手指走一遍。录屏和原型片并排看，节拍差不超过 2 帧；扫描没有硬切；5 种尺寸都能用。

### P3 · 档案页
- 开、关档（原型的时间线；标题全程不动；关档先重新加密）；
- **窗口：** 窗口静帧上盖纸色、电路退成线稿，然后放该档案的演示（复用 `ui/demos` 的组件，按竖屏窗口改样式）。每个演示标出一个"核心元素"（`data-core`）：密钥的光从芯片沿一条直角走线跑进这个元素，演示才解密出现（A4、A7）。X-001 用原型里那套"芯片就是 SafeAdapter"的版本；
- **正文：** 窗口下面是纸面长文，包括该档案全部章节、数字、证据、相关档案、外链；向下读时窗口自然滚走，顶上出现一条细栏（`← All files · X-001`）；
- **特殊档案：** X-000 的红队游戏能玩（接口在生产环境）；V-FILE（访客自己）；YW-000 的门进内景，按 P0 对 H6 的结论做；
- **验收：** 每个条目都能打开、读完、返回；每个演示截一张；在窗口里没有溢出、没有被裁；开、关档录屏扫描没有硬切。

### P4 · 第一面：按住指纹进入
- 手机上的指纹页：指纹一出现就能按住；按住时三句话快速走完并封存（约 2 s，指纹的纹路随按住时间被"读取"）；松手太早就停在原处；3 秒不碰就像现在一样自动播放；Skip 保留；
- 封存后接 `entrance.mp4`（在指纹页期间预加载好）；没加载完就停在封存画面等待，不出现空白。
- **验收：** 按住、自动播放、Skip 三条路径各录一遍；从首字节到封面可读：按住路径 ≤ 6 s，自动路径 ≤ 14 s（4G 限速下测）。

### P5 · Index、联系、简历、横屏
- **Index：** 纸面列表，分组和桌面一样。点任意条目：列表让开，露出它的停站静帧，接着播开档短片；
- **联系：** 邮件、LinkedIn、GitHub、简历 PDF 都能点通；
- 横屏提示；`prefers-reduced-motion`；没有 JS 的情况。
- **验收：** 每个链接留请求记录；横屏截图；减弱动效时的录屏。

### P6 · 打磨与全面质检（PM 主导，执行子代理配合）
- 原型里已知的三处：封面前排发光的盘压一压；系统图节点改成电路焊盘的样子；跨抽屉的平移别太长太猛；
- **排版：** 手机上所有文字 ≥ 11 px，有意义文字的对比度 ≥ 4.5:1，文字永远落在纸色底上；
- 去掉浏览器默认的蓝色点按高亮；处理安全区、`dvh`；iOS 上短片内联播放；安卓上禁止下拉刷新；
- **性能：** 首屏 JS + CSS（gzip）≤ 250 KB；整个流程长任务 ≤ 50 ms；内存不爆（iOS 的图片解码上限）；
- 审查时（R6 问题表）的第 1–4、8 条，在新版里逐条确认已经不存在。

### P7 · 收尾与交付
- `.claude/verify.json` 全绿（类型检查、lint、单测、构建、冒烟）；桌面端端到端走一遍，和 `main` 截图对比没有差异；
- `reviewer` 子代理对照这份计划做独立审查，影响正确性和需求的问题全部修掉；
- 用户在自己的手机上（局域网 `p3-lan`）完整走一遍：这是最终验收；
- 合并和部署**等用户点头**。

## 8. 风险

| 风险 | 预案 |
|---|---|
| iOS 交接闪帧（H2） | 双缓冲：两个 video 元素交替，下一段播出第一帧后才切；还不行就换成图片序列（体积换稳定） |
| 资产太大 | 短片用 crf 24–26；非精选条目的开、关档降到 1.5 倍 |
| 内景太重（H6） | 六站烘焙成静帧，加网页层的步骤标注 |
| 演示放不进窗口（H7） | 该演示改成两段：窗口里放主图，其余步骤放到正文第一段 |
| 内容以后要改（比如 Coast Capital 的实习结束） | 重新跑 `npm run phone:bake`；manifest 的哈希会变，缓存自动失效 |
