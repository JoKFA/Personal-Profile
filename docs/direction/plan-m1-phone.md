## 0. 目标与非目标

**目标：** 用户能把 yaotingw.com 发给任何人，或者当面掏出手机演示。在竖屏手机上：
1. 画面和原型片一致：同一个准星、同样的弹簧、同样的开关档、真解密；
2. 每一步都用手指自然完成：按住指纹进入、上下滚动换档案、点开、读完、返回、Index、联系、简历；
3. 任何手机都流畅、清楚：手机上**不跑整片实时 3D**；
4. 内容完整：Index 里的每个条目都能打开、读完、看到演示；
5. 没有一处坏的、读不清的、硬切的、闪白或闪黑的；
6. 低电量模式、弱网、读屏、返回键、刷新、分享链接这些真实情况都有交代。

**非目标：**
- 桌面版的**行为**变化（判定办法见 E8）；
- 访问统计、V-FILE 文案（路线图 P3.3，另做）；
- 桌面才有的功能：粉碎、图例滤镜、悬停标签、UEBA 告警；
- 横屏：只显示一张纸面提示，转回竖屏回到原处；
- 宽度 ≥ 900 的平板和电脑：走桌面版；
- §8 以外、没经用户批准的新文案。

## 2. 架构（PM 定，执行不改）

**一句话：** 画面全部在本机 GPU 上用真引擎预先渲好（"烘焙"），手机只负责摆图、放短片、画网页层。

### 2.1 画布与适配
- **母版：** 烘焙视口 **480 × 960** css px。构图以准星框为中心，四周多渲一圈"出血"，给各种屏幕比例留余量。静帧按 **2.5 倍**（1200 × 2400，约 2.9 MP，解码后约 11.5 MB），短片按 **2 倍**。原型片按 390 × 844 拍，网页层的位置换算到母版坐标。
- **停站的适配规则：** 可用带 = 顶栏下沿到底部面板上沿。舞台缩放 `s = min(屏宽 / 准星框宽 × 0.62, 可用带高 / 准星框高 × 0.9)`，准星框在可用带里水平居中、竖直居中。出血保证四周永远是档案馆，不会露底。
- **窗口（打开以后）的适配规则：** 盘面宽度 = 屏宽，顶端对齐；下面是纸面正文。
- **测试尺寸用浏览器里的实际可视区，不是屏幕分辨率：**
  - 375 × 548（iPhone SE，Safari）
  - 390 × 664（iPhone 13/14，Safari 工具栏展开时）
  - 390 × 750（工具栏收起后）
  - 430 × 740（Pro Max，Safari）
  - 360 × 640、412 × 780（安卓 Chrome）
  - 412 × 860（0.43 比例的长屏）
- **网页层的字不随 `s` 缩放：** 文字字号是固定的 CSS 值，最小 11 px。

### 2.2 浏览靠原生滚动
- **页面结构：** 正常的竖向文档，分段为封面 → 01 → 02 → 03 → 04 → Index 与联系。每段约一屏高，用 `scroll-snap`，`scroll-snap-stop: always`。档案馆舞台用 `position: fixed` 固定在后面，准星和顶栏固定在前面（A1）。
- **滚动时：** 纸面（面板）跟着手指走，这是对纸的直接操作。当下一段进入视口超过阈值（约 35%），舞台开始播放这两站之间的平移短片；吸附完成时盘已接近落定，字在盘落定时解密（A5）。往回滚就播反向的平移。一次快速甩动只前进一站（`snap-stop`）。
- **好处：** 浏览器工具栏会自然收起；读屏软件可以逐段读；邮箱等文字能长按选中；平移短片不需要"用户手势"才能播（只要静音内联播放被允许）。
- **打开档案：** 点 Open 或点盘 → 锁住这段滚动 → 播开档短片 → 进入档案页（它自己的滚动）。

### 2.3 资产（`npm run phone:bake`，可重复）

| 资产 | 内容 | 格式 |
|---|---|---|
| `entrance` | 入场的浪（原样）接推近到封面，约 5.3 s | 2x，H.264 |
| `stop-<id>` | 每个**在 Index 里出现的条目**都要一张停站静帧（盘升起、外壳变清、其余灯退后）。不包括技能和证书条目 | 2.5x，WebP |
| `pan-<a>-<b>` | 精选五站之间相邻的平移，前后两个方向，共 8 段 | 2x |
| `open-<id>` / `close-<id>` | 每个条目的开、关档（关档单独渲，不是倒放） | 2x |
| `window-<id>` | 开档最后一帧，盘面铺满屏宽 | 2.5x |
| `door-YW-000` | 主档案的门 | 2x |
| `manifest.json` | 文件名（**带内容哈希**）、帧数、帧率、准星框；开、关、门三种短片每一帧的盘面四角；芯片中心；**输入哈希**（`entries.ts` + 导演 + 引擎文件的哈希） | — |

**规则：**
- **文件名带内容哈希。** `vercel.json` 给 `/phone/*` 加 `Cache-Control: public, max-age=31536000, immutable`（站点其余部分仍是 `no-store`）。
- **资产直接进 git，不用 LFS。** 预算：仓库里手机资产总量 ≤ 45 MB。超了就先降非精选条目的码率。
- **过期检查进 `verify`：** 输入哈希和当前源码对不上就失败，提示"内容变了，重新烘焙"。
- **烘焙不用热更新的开发服务器：** 用 `vite build --mode bake` 出一个专门的构建，再 `vite preview` 出来渲染，改源码影响不到正在进行的烘焙。
- **烘焙前先确认真 GPU：** 读 `WEBGL_debug_renderer_info`，如果是 SwiftShader 等软件渲染就中止。

### 2.4 交接与播放（最大的风险，P0 和真机定数值）
- **图到短片：** 图先不动，短片的第一帧真的画出来（`requestVideoFrameCallback`）以后才把图隐藏。**短片到图：** 静帧垫在下面，短片 120 ms 淡出。任何时候不露空白、不露黑。
- **视频池：** 两三个 `<video>`（静音、`playsinline`）复用，换 `src` 播不同短片。在第一次按住指纹时，对池里每一个都 `play()` 再 `pause()`，借这次手势把它们"解锁"。相邻的短片（这一站的开档、前后两段平移）提前挂上并缓冲。
- **播放被拒的模式：** `play()` 一旦报 `NotAllowedError`（iOS 低电量模式、省流量），整个会话改用"静帧 + 交叉淡化"，网页层照常走。短片没缓冲好时也临时用这一套，不等待。
- **网页层跟媒体时间：** 播片时每一帧按 `requestVideoFrameCallback` 的媒体时间取值；没在播片时用应用时钟。**不用 CSS transition 做任何和画面同步的东西。**
- **内存：** 同时解码在内存里的静帧 ≤ 6 张，离开的立即释放。

### 2.5 外壳、内容与隔离
- **入口：** `PhoneApp` 每次加载判定一次：`pointer: coarse` 且屏幕短边 < 600 → 手机外壳，和当下横竖无关；横屏时外壳只显示提示。手机外壳**不静态引入**桌面的 `CasefileApp`、`Hud`、`archive.css`、three.js。内景是唯一可能动态加载 three.js 的地方（见 H6）。
- **内容共用，不复制：** 从 `FileView.tsx` 抽出一个纯内容组件（章节、数字、故事、证据、相关、外链），桌面和手机共用。演示组件（`ui/demos`）通过一个窄接口取它们需要的东西：桌面接 `Archive`，手机接 `PhoneCtx`。要加一个测试：每个条目在两种接口下都能渲染。
- **CSP（生产是 `style-src 'self'`，没有 `media-src` 例外）：**
  - 不注入 `<style>`，不在 HTML 字符串里写 `style=`；只用 CSS 文件加 `element.style`。
  - 不用 blob 视频，视频直接用同源文件。
  - 手机的端到端测试必须跑在 `vite preview` 上（它带 CSP），出现任何 `securitypolicyviolation` 就失败。
- **桌面隔离：**
  - 引擎里的实验钩子和导演整理成 `labHooks`，只在 `import.meta.env.MODE === 'bake'`（以及开发模式）存在；生产构建里没有。
  - 删掉 `includes('phone')` 这种模糊触发；`degrade` 的守卫还原。
- **状态和 URL：** `/` 是浏览；`/projects/:slug` 是档案页。浏览站点用 `replaceState`，不进历史栈。各种进入方式见 §2.6。

### 3.1 P0 的结论（10-12，`evidence/M1-P0/report.md`，提交 `14a2c59`）
- **H2 ✅（用户 iPhone Safari 实测，10-12："整个画面是流畅的"；预览部署 + P0 测试页）。** 低电量模式（H9）待用户补测。
- **H2 ✅（Chrome）：** 4 组配置里 0 帧空白；从点按到第一帧 35–54 ms（已缓冲）、50–83 ms（冷启动）。iOS 待真机。Playwright 的 Windows 版 WebKit 没有 `requestVideoFrameCallback`，它的数字作废。
- **H3 ⚠️ → 定：** 网页层**提前 1 帧**取值（在合成器上它天然慢 1 帧；提前后 42/53 帧对齐，其余差 ±1）。
- **H4 ✅：** 首屏约 1.5 MB；一次典型浏览约 5–8 MB。
- **H5：** 证实"按宽度缩放、顶端对齐"在浏览器实际可视区下不行，改用 §2.1 的"准星框放进可用带"规则（v2 已写）。
- **H6 ❌ → 定：** 内景在降速 4 倍时约 10 fps，而且一启动就降到低画质，所以**六站改为烘焙**（静帧加网页层的步骤），手机上完全不加载 three.js。
- **H10 → 定：** 烘焙不可能逐字节一致。两次的验收改为：同一帧的平均差 ≤ 0.5%。
- **烘焙时冻结"呼吸"**（美术决定）：档案馆的待机起伏在烘焙画面里固定为 0。静止就是静止（A2），PV 的停顿也是静的。不冻结的话，短片末帧和静帧对不上（实测 6.4%）。
- **停站要约 3 s 才完全落稳**（弹簧尾巴很长）。定：平移片渲 2.4 s，最后 6 帧逐帧混合到标准停站静帧，保证交接零跳变。开档片 2.0 s，末帧和窗口静帧的差 0.74%，不用混合。
- **开、关档时舞台的缩放：** 按每帧的 `cam`（镜头进度），在"停站适配"和"窗口适配"两个缩放之间插值，和画面同步。
- **芯片中心按像素实测**（原型尺寸下是 213, 402）；解析投影偏 20 px，原因未明，以实测为准。
- **测试浏览器：** 一律用 `channel:'chrome'`（自带的 Chromium 不放 H.264）。

### 3.2 P1 的结论（10-12，提交 `cdaf0f7` `f7c2939` `78e6a1d`，证据 `evidence/M1-P1/`）
- **已生成：** 19 个停站（YW-000、X-000…X-009、SR-01…04、ED-01…03、V-FILE）、8 段平移、19 条开档、19 条关档、19 张窗口静帧、入场、门。48 条短片扫描都没有硬切；首尾和静帧的差最大 1.14%；两次烘焙的差 ≤ 0.5%；生产构建里实验钩子为 0。
- **体积超了**（总量 50 MB、首屏 6.6 MB）。**定：**
  - 入场：720 宽 crf 26，在残差 ≤ 1.5% 处截掉落定的长尾，最后 8 帧过渡到封面静帧；
  - 平移：720 宽 crf 24；
  - 五个精选的开关档：960 宽 crf 24；
  - 其余开关档：720 宽 crf 28。
  - 预计首屏约 2.4 MB、总量约 30 MB。
  - 短片分辨率低于静帧，所以"图到短片"那一步，图在 100 ms 内淡出，把清晰度的变化藏住。
- **§2.1 的适配规则在矮屏上露底**（375×548 上有 57–61% 盖不到）。**改为：** 缩放 `s = max(铺满, min(合适, 1.1))`，其中"铺满"= `max(屏宽/母版宽, 屏高/母版高)`。准星框放不进可用带时，让盘的上沿贴住可用带顶，盘座压在面板下。可视区高度 < 600 时面板用紧凑版（150 px：眉题、标题、Open）。准星四点框住盘露出来的部分。
- **X-000** 是封存的黑盘，窗口里没有芯片可对。芯片位置用其余 18 个盘的平均（相对位置一致）。它的窗口内容在 P3 单独设计。
- **门**是从引擎默认视角起的，和封面接不上。P3 和内景烘焙一起，从封面取景重渲。

  - 18 个条目在 390×664、375×548 上都能打开、读完、返回；交接 0 空白帧；网页层与画面误差在半帧内。
  - 档案页改成整页文档滚动（Safari 工具栏能收起），关档时浏览位置原样恢复。
  - 手机上去掉全部柔和阴影和渐隐边，换成 1 px 细线；顶栏 Index/Contact 在每一站位置相同。
- **烘焙时钟（P3c 发现）：** 之前的假时钟没暂停，每帧实际 41–50 ms，片子快 3–25% 且不均匀。**定：** 全部资产按精确 40 ms 重烘（`e4f2997` 起）。平移和关档在"首帧与静帧差 ≤ 1.5%"处截断，不早于 2.4 s（`0fe7389`）。
- **门和离开（`e4f2997`）：** 镜头从第 0 帧跟着盘走，盘不离开画面；离开时盘直接落回封面停站姿态，不先落槽再升起，没有叠影。
- **内景体积：** 5.54 MB（预算 12）；36 个接缝全部 < 2%。
- **指纹页（P4，`3398b02` `e0595c5` `fac5f26`）：**
  - 按住 2.0 s 封存；4G 下封存到入场首帧 41 ms；慢网封面 12.1 s 可读。
  - 7 种尺寸 × 3 个阶段没有文字压线或互相碰撞；SE 上指纹 104×148。
  - 名字从首帧到顶栏一直不动；`<body bgcolor>` 让首帧是纸色（不受 CSP 限制）。
  - 浏览器出第一帧之前的白屏（慢网约 1.2 s，等阻塞样式）**接受**，不动渲染阻塞的 CSS。
  - 首帧名字用系统字体，指纹页出现时原位换成 Manrope；不做子集字体。
- **节奏（10-14 定）：** 精确时钟下开档窗口在 1.68 s 落定，原型是 1.36 s，用户批准的是原型片的节奏（约 1.25 倍）。**定：** 入场、平移、开关档用均匀的 50 ms 一帧（每帧暂停时钟、走 50 ms，按 25 fps 播放）；门、intro、六站、飞行、out/in、离开保持精确 40 ms（桌面原有节奏，内景要留读字时间）。
- **渐晕（10-14 定）：** 桌面页面的 CSS 渐晕（`.cf::after`）被烤进了每张画面，窗口上三分之一被洗白、标签看不清。**定：** 手机的烘焙画面只要场景像素，全部去掉渐晕。和节奏一起重渲一次。
- **X-000（`7f698fa` `4e34926` `4230671` `1708ac3`）：** 黑盘的外壳是不透明的，正对时边缘读成一大团暗光。**改为：** 开档时外壳随转身滑开（引擎里门本来就有的动作），露出板、走线和芯片，边缘清楚。
- **内景运行时（`c4db9a8`）：** 芯片同步 710/714 在 1 帧内（4 个是测量误差）；七种尺寸芯片不出构图区、不压字；手机代码块不含 three.js。**返工四处：** 挑选区域时先把场景滚回视野；纸面中间约 158 px 的空洞；逐个检查录屏扫描出的尖峰；从结果跳档案改成 out-i 加速 → 180 ms 交叉淡化 → 开档（目标 ≤ 3.0 s，原来 5.3 s）。
- **P6 待办（审查中记下）：** 跨抽屉平移不要太长（50 ms 节奏后复看）；内景芯片同步由独立复验再查。

### P3c · YW-000 的门和内景（10-13 定；H6 不过，全部烘焙）
**流程：** 封面或 Index 点 YW-000 → `door`（从封面停站起：盘站正、镜头绕到正面推到芯片）→ 匹配剪切 → `intro`（俯视芯片 → 抬起越过枢纽 → 流进第 1 站）→ 第一次进入自动导览 6 站 → 停在第 6 站的结果上。YW-000 不再走普通开档：`open/close/window-YW-000` 从烘焙里去掉。
**取景：** 主体构图区在母版里固定为 `x 0–480, y 64–536`（宽高比 1.02，走 `PHONE_KEYS`）；舞台按窗口规则（`s = 屏宽/480`，顶对齐）。区域下沿以下是纸面。
**节奏：** 手机只有一种速度，就是桌面导览的速度（每站 5.0 s，飞行 1.8 s）。挑选某一站也播同一段片子，停在结果上；点步骤 = 跳到片子里那一步的时间并暂停。
**资产（同一套烘焙流程，只用真引擎的门、内景和运行时的代码路径）：**

| 资产 | 内容 |
|---|---|
| `door-YW-000` | 封面停站 → 剪切（已有，首帧要和封面静帧对上 < 2%） |
| `space-intro` | 剪切后第一帧 → 第 1 站 p = 0 |
| `space-<i>` × 6 | 第 i 站 p 0 → 1；每帧记下每个芯片锚点的母版坐标和可见性；记下结果帧号和证据板的屏幕点 |
| `rest-<i>` × 6 | 第 i 站 p = 1 的静帧（降级、减弱动效、播放被拒时用） |
| `fly-<i>-<i+1>` × 5 | 导览：第 i 站结果 → 第 i+1 站 p = 0 |
| `out-<i>` × 6、`in-<i>` × 6 | 第 i 站结果 → 枢纽；枢纽 → 第 i 站 p = 0（`out` 就是桌面离开时的那段飞行；任意挑选 = out + in，中途停在枢纽的全景上，作为一次换气） |
| `hub` | 枢纽静帧 |
| `space-exit` | 枢纽 → 倒放 intro → 倒放门（桌面的 `backSpeed`）→ 封面停站；带盘面四角（准星落回封面） |
| `thumb-<i>` × 6 | 证据缩略图，用桌面缩略图的取景 |

- **确定性：** 内景的 `time` 冻结（同 `idle0`）；每段的首末帧和相接的静帧或片段首帧差 < 2%；`retained` 按导览顺序的真实状态。
- **数据：** 内景的锚点等写进单独的带哈希 `space-<hash>.json`，进入 YW-000 时才加载；manifest 里只放它的文件名。
- **预算：** 内景 ≤ 12 MB；全站手机资产仍 ≤ 45 MB。
- **运行时（`PhoneSpace`）：** 共用 `space/content.ts`（区域文案、芯片、步骤）和 `space/station.ts` 的常量，不引入 three.js。芯片只显示 `phone: true` 的，按媒体时间取锚点，放在纸色底上，限制在构图区内。纸面上依次是：编号和标题、四个步骤点和当前一句、结果和 `Open X-…` 链接、六个区域、Pause/Replay/Evidence n/6，然后是共用正文（个人与教育）和证据列表。滚动正文 = 在读，演示暂停（同桌面）。
  - 导览中途挑别的站：180 ms 交叉淡化到 `out-<i>` 首帧，接着走 out + in。
  - 离开：`out-<i>` + `space-exit`，回到封面。
  - 从结果里点 `Open X-…`：离开片段加速 1.5 倍 → 目标停站静帧交叉淡化 → 开档（同"相关档案"）。
- **验收：** 导览全程和每种挑选、离开路径各录一遍，扫描没有硬切（门和 intro 之间的匹配剪切单独标出）；芯片和锚点误差 ≤ 1 帧；七种尺寸截图，芯片不出构图区、不压字。

### P4 · 第一面：按住指纹进入
- 手机上的指纹页：指纹一出现就能按住。按住时三句话快速走完并封存，约 2 s，纹路随按住被"读取"；松手太早就停在原处；3 秒不碰就自动播放；Skip 保留；文案 `Hold to verify`；

- **验收（网络条件写死）：**
  - **4G**（9 Mbps 下行、60 ms 往返）：按住完成后 ≤ 0.3 s 开始入场；全程等网络的时间 ≤ 0.5 s。
  - **慢网**（400 kbps、400 ms）：从不露空白；短片来不及就用静帧和交叉淡化；可读的封面在 20 s 内出现。
  - 按住、自动、Skip 三条路径各录一遍。

## 6. 编排

```
P0 探路 ──▶ 真机检查 ──▶ PM 定数值
   └▶ P1 烘焙（bake 构建，不碰开发服务器）─┐
```

- **不并行：** 改同一批文件的工作包不同时进行。
- **真机测试走 HTTPS，二选一，需要用户点头：**
  - (a) 用 Vercel CLI 发一个预览部署（不推送 git；有真 CSP 和 `/api`；链接不公开但能访问）；
  - (b) 本机用 mkcert 起 HTTPS，用户在手机上安装一次根证书。
