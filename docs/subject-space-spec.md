# 主档案 YW-000：进入硬盘的工作空间（规格 v2，2026-10-02）

v2 = v1 + **2.5D 转向**：用户看过程序化 3D 小模型后判断“模型廉价、网页渲染不到视频的质感”，要的是**质感与信息**而不是精模 —— 质感 = 入场动画那种克制/高科技/清爽/舒适/不扎眼（动画 + UI + 运镜的组合），信息 = 访客一眼理解。因此六个领域的内容从“3D 实体模型”改为**画出来的 2.5D 图版**（陶瓷平板 + 线稿图标 + 玻璃片 + 发光信号线），镜头、匹配剪辑、双层节奏、证据累积等其余要求全部保留。

替代：Codex 的 space-sample（已删）、`casefile-spec.md` §25 的俯视攻防短片（已删除，见 §9）、§28 被撤回的原型接入。
设计来源：用户 2026-10-02 的 14 条完整要求（下文 R1–R14）+ 同日 2.5D 转向；参考视频 BV1rr4y1b7sz 约 40–47 s（帧在 `.codex-runtime/design/pv/`）。

## 0. 目标 / 非目标

**目标**
1. 主档案是工作空间的入口：入场波动结束 → 主档案升起 → 转到正面迎向屏幕 → 贴近占满视野 → 视角进入硬盘 → 无感切镜头进入内部（R2）。
2. 内部是另一尺度的、宽阔有纵深的整体空间；六个领域相距很远，展示一个领域时看不到其他领域的对象与标签（R3）。
3. 内部用真实的镜头组织来展示六个领域，每个领域有自己的构图（R4）。
4. 六个领域各有独特的象征对象、动作与证据；可读信息在 HTML 层；证据持续累积并有 2×3 索引（R9–R11）。
5. 右侧完整个人档案不变（R13），加 CCNA / Security+ 徽章；手机重新组织顺序（R14）。
6. 延续站内视觉调性与 UI 语法（R7、R8）：全幅场景、无盒子、hairline、站内 token。

**非目标**：不改履历事实、不改 Gate / 入场浪潮 / 其他档案；不引入新依赖（three r183 已有）；不做音效；不追求写实建模。

## 1. 用户要求 → 设计决定

| 要求 | 决定（现状） |
|---|---|
| R2 无感切镜头 | **匹配剪辑**：外景 door 模式（纯函数 `scene/door.ts`：立正 1.1 s、0.5 s 起推近、3.0 s 结束；对数插值距离 72 → 2.0，焦距比 = 推近^2.2 使硬盘只会变大，终 fov 24.5°，视线移到 die；缓动用三次 smoothstep，推近速度是一条从 0 起、1.2 e-folds/s 达峰、收到 0 的钟形）。切点处 `measureHandoff()` 取 {glow, fov, dieFrac}。内景首帧是**硬盘自己的 GLB 组件**（陶瓷、香槟、雕刻、钛，放大 `HUB_SCALE`≈26）正俯视，贴蚀刻面贴图 `etchMaterial`；切点后 die 浮雕 `1+2.4*smooth` 挤出。色调（暖色 tint、曝光 `introExposure` 0.76）与外景平均色 (200,181,158) 数值对齐，几何同位（像素位置核对）。再叠 0.45 s 的 2D `veil` 画布溶解。 |

## 2. 架构

```
Archive (scene/archive.ts)         ── 外景：入场浪潮、开档、door 模式；suspended 时不画
   └─ interior（内景由 archive 的同一个 renderer/canvas 画）
CasefileApp.openEntry(subject)     SpaceStage (space/scene.ts)：自己的 Scene + EffectComposer
   beginOpen → readDrive →           ├─ world.ts：栅格地面、蚀刻贴图、硬盘 GLB 组件（hub）、总线
   beginDoor → clock.restart →       ├─ stations/*.ts：六站，每站 Station.set(p, t, appear) 纯函数
   startRuntime → setCut/setFile     ├─ shots.ts：镜头（纯函数，桌面 / 手机）
FileView (subject)                   ├─ clock.ts：单一时钟/控制器（纯 TS，有单测）
   └─ <SpaceExhibit/>               └─ runtime.ts：rAF、隐藏暂停、证据缩略图、exit()
      （HTML：字段、导航、证据索引）
```

- **内景与外景共用同一个 `WebGLRenderer`/canvas**（不是第二个上下文）：内景进入时外景 `suspended`，切镜头 = 换哪个场景在画。内景 composer：RenderPass → GTAO(high) → Bokeh → 动态模糊 → SMAA → OutputPass。着色器在构建时用 `prepare()`（离屏 RT + 代理对象）预编译，分帧构建（`boot.ts`），不卡主线程。
- **站 = 进度的纯函数**：`Station.set(p, t, appear)`，无隐藏状态；步骤起点 `STEP_AT=[0,.26,.55,.86]`，结果 `RESULT_AT=.86`，证据板 .88–1 落位；`appear` 在飞行中升起，所以第一眼就有图版。重播、跳步、停在结果、回到已完成站都走同一份代码。
- 降级：内景无法构建 → 主档案像其他档案一样直接打开（右栏完整、左侧没有展示）；reduced-motion → door 直接完成、内景停在首个结果；无 WebGL → 文件页可读索引。

## 3. 时间线（秒，2026-10-02 按“缩短并更流畅”调过；实测见下）

**进入（点击 → 第一个领域开始播放，约 7.6 s，原 12.9 s）**
- 开档读盘约 1.9 s：升起、弹出、读取光扫过表面。**读盘光扫完、die 闪过（约 1.05 s）就开始 door**，不再停顿 0.7 s 等读盘收尾。
- **door 3.0 s**（原 4.5 s）：立正 1.1 s，0.5 s 起推近，1.8 s 起视线移向 die，3.0 s 切。可 Skip。
- **内景 intro 2.6 s**（原 3.0 s + 首飞 2.4 s）：0–1.6 s 俯视 die 浮雕挤出、倾斜升起到 hub（主体同时被镜头偏移移进左区，右栏解密）；**1.1 s 起不在 hub 停留，直接顺势飞向第一个领域**（与领域之间的飞行同一条弧线），2.6 s 到达并开始播放。没有单独的“首次飞行”。
- 切点之后程序性卡顿已消除（见 §8）。

**导览/查看（未改）**：每领域约 5 s，领域间飞行 1.8 s，总约 41 s；选领域停导览，4 步 ×1.65，终态停住。

**退出（Esc → 回到档案，约 2.7 s，原 4.1 s）**：飞回 hub 0.55 s → intro 反向 0.5 s → door 反向（3.0 s 的 door 以 2.7× 倒放，约 1.1 s）→ 硬盘落回。

实测（真实 GPU，生产构建，1440×900 与 390×844，`scratchpad/timeline.mjs` 每帧取样）：door 开始 1.95 s、切点 4.96 s、intro 结束 7.4–7.6 s；退出 2.7–2.8 s。

## 7. 视觉底线（自检清单）

站内 token 之外无写死颜色；3D 上无字；标签最小 10.5px（`.space-chip .lbl` 已由 9.5 改为 10.5）；左侧无姓名/大标题；主体占左区高度 ≥ 55%；无彩虹；无整片泛黄/泛绿；线条不实体化；DOF 让主体锐利。

## 8. 风险与对策

内景首次渲染的编译/纹理上传卡顿 → `prepare()` 预热 + 分帧构建；手机分级 → `quality.ts`；证据缩略图每次离屏渲染 → 只在结果完成后一次。

**档案降级会让内景预热作废（2026-10-02 发现并修复）**：`Archive.degrade()` 原先关掉 `renderer.shadowMap.enabled`，而这个开关在档案与内景之间共享，会改变内景所有受光材质的着色器键 → 切点处首帧与第一个领域出现时在手机上各卡 0.6–0.8 s（17 个着色器现场链接）。现在降级只让档案自己的主光停止投影（`stage.setShadows(false)`），内景预热的程序保持有效；手机视口实测切点后慢帧由 733 ms 降到 ≤100 ms，开档期间新链接的着色器由 17 个降到 1 个。
